# FanBar 设备兼容性 · 入口与设计稿 v0.1

本次只产出设计稿，不改应用行为。所有设备与能力结果均为示例，没有读取真实设备或发送报告。

## 入口

- 常驻：设置 → 通用 → 设备兼容性。独立分组置于顶部，整行可点击，第二行显示结论。
- 首次使用：现有欢迎页加入检测摘要及“查看详情”，保留打开菜单栏面板的主按钮，不新增强制向导。
- 异常：散热页已有服务异常提示位置加入“查看兼容性”，根据原因给出权限、临时故障或不适用说明。
- 三个入口打开同一兼容性详情。返回时应回到来源页面；原型返回按钮目前演示返回通用设置，实际实现应保存来源。

## 视觉系统

模式：Extension；保留散热／外观／通用三标签、560pt 窗宽、原生工具栏与设置分组。
设计读数：视觉变化 2 / 动效 1 / 密度 6 / 资产依赖 3 / 品牌一致性 10。
阅读场景：笔记本近距离使用，重点是结论、限制和下一步。
系统字体 SF / PingFang；13px 正文、11px 次级、21px 详情标题；12px 卡片圆角；24px 内容边距；分组约 23–28px。
使用现有系统蓝操作色、语义绿成功色和琥珀色权限／暂时失败提示；不以颜色单独表达状态。
窗口沿用原生阴影，卡片用细边框；状态切换仅轻量反馈，支持 reduced-motion。

## 能力与证据

CPU/GPU 温度、风扇读取、SSD/电池温度、手动调速、智能温控逐项判断；正式实现可展开各传感器，不应以一个成功读数代表同组全部能力。
“已读取”来自本次实际读数；“控制服务就绪”与“实际调速已验证”分开；一次失败为暂时不可用，不写入机型不支持结论。
无风扇设备明确展示风扇控制“不适用”；没有读到风扇不等于设备没有风扇，需要可信机型信息。
只读检测不能验证控制，使用真实操作结果逐步更新；不自动改变转速。
随应用发布兼容性记录，本机匹配；公开记录须显示来源、适用版本、验证时间，矛盾报告保留差异。
页面可滚动，不把详细报告全部塞入 600pt 窗口。

## 隐私与上传

检测默认本地完成，不联网，不弹隐私授权框，不安装或授权控制服务。
兼容性报告入口是次级操作：预览 → 未默认勾选的单次同意 → 提交。
字段白名单：机型标识、芯片类别、系统/应用/Helper 版本、能力状态、标准原因码、每次报告随机编号。
不含序列号、唯一设备标识、用户名、主机名、文件路径、进程、温度历史；问题诊断日志走独立入口，不捆绑。
报告提交与重试必须对应用户主动操作，不因重新检测而自动上传。
上线前必须确定接收方、原始报告保留期限、删除方式、传输和权限措施、网络元数据策略；在预览中披露。此设计稿不虚构已经存在的隐私承诺。
没有稳定设备标识时只能统计报告数，不能宣称独立设备数。

## 原型覆盖

四种入口/页面、四种设备状态、明暗外观、重新检测、报告预览与单次同意。所有上传为模拟；部分原有应用动作使用解释提示。
当前设计稿是 HTML 可点击视觉样稿，实际应用应使用 SwiftUI / AppKit 原生控件和 SF Symbols。
